# 月迹产品与交互设计

## 1. 产品定位

月迹（hercula）是一个只在本机工作的月经记录工具。它不要求注册，不上传经期数据，不接入广告或行为分析。用户打开应用后可以快速确认今天是否来月经，并从同一界面向下查看历史与导入导出。

### 首版目标

- 3 秒内完成“今天来月经”的记录。
- 能看见每次经期的开始日期、持续天数和当前是否仍在记录。
- 用明确标注“估算”的方式显示下一次经期，不把算法结果包装成医疗结论。
- 当前可以从 JSON 恢复数据，也可以导出可读、可迁移的 JSON；文本和图片导入保留为后续阶段。

### 不在首版范围

- 症状、情绪、经量、用药、排卵、备孕或疾病诊断。
- 云端同步、账号体系、推送提醒、广告、统计 SDK。
- 与系统健康数据或其他设备自动同步。
- 依赖联网大模型的解析。

## 2. 页面与手势

应用只有一个 UIAbility 和一个入口页面，入口页面内部由两个满屏展示页组成：

### 页面一：自绘月历

- 页面只保留品牌和月历主体，不显示“记录身体，也记录时间”或“向上滑动查看历史”等说明性文案。
- 月历完全由 ArkUI `Grid`/`ForEach` 自绘，不使用系统标准日历模板；不显示星期标题，不显示月份两侧箭头。
- 年、月是两个可点击的圆角选择控件。点击后展开应用内的年份/月份选择面板，选择后立即跳转到对应月份。
- 月历内部使用横向 `Swiper`，向左/右滑动切换上一个/下一个月；外层仍使用纵向 `Swiper`，一次手势切换到历史统计页。
- 点击当前月或可见的相邻月份日期均可切换标记；未来日期无响应。首次点击新增经期日，再次点击立即取消，不弹确认框；每次变化立即写入本地 Preferences。
- 已标记日期使用低饱和粉红色圆形底；当前日期使用浅蓝色描边或底色辅助识别，颜色不作为唯一状态表达。
- 月历卡片使用紧凑的 6 行布局，不固定成过高的手机卡片。内容区域最大宽度约 720vp，在平板和宽折叠屏展开状态居中，避免日历随屏幕无限拉伸。

### 首次打开

- 第一次打开应用显示一次欢迎弹窗，明确说明“点击日期记录，再次点击取消”。
- 弹窗提供“开始记录”和“导入数据”两个动作；任一动作后不再重复显示。导入动作继续沿用历史页的 JSON 文件选择与预览确认流程。

### 页面二：历史统计

- 通过一次向上/向下手势切换到历史页，页面切换按整页吸附，不采用自由滚动。
- 上半部为无边框的横向水平柱状图：每一行是一次经期，日期作为左侧行标签，柱条长度表示持续时长。最后一条未结束记录以“截至今天”计算，并带有“进行中”标记。
- 不绘制持续天数坐标轴、网格线、刻度或外框；每条柱的持续天数显示在柱条末端，例如“5天”。空数据状态显示引导，不显示伪造柱子。
- 图表下方同步提供文本摘要，以便无障碍朗读和在窄屏上阅读：例如“2026-08-01，持续 5 天”。
- 有历史记录时，导出使用标题行最右侧的圆形图表按钮；无历史记录时，空状态内展示导入按钮。导入完成后先展示解析预览与冲突数量，用户确认后才写入本地数据。

确认版图表结构：

```text
日期标签        水平柱条                         末端时长
2026-04-02      █████                            5天
2026-05-01      ████                             4天
2026-06-03      ██████                           6天
2026-08-01      █████                            进行中
```

柱条不带边框，页面不显示持续天数坐标轴；日期是记录行的唯一轴向信息，时长由柱条长度和末端文字共同表达。

### 导入流程

1. 当前点击空状态的“导入已有记录”。
2. 通过系统 DocumentViewPicker 选择 JSON 文件并取得临时 URI 授权。
3. 先解析为候选日期，不直接覆盖现有数据。
4. 显示有效日期和待新增日期，用户确认后合并；已有日期保持幂等，不创建重复记录。
5. 文本和图片导入的入口、候选片段和失败原因留待阶段 2/3 定义。

首版“任何形式的文本”定义为：应用尽力识别常见日期表达式，但不承诺识别所有自然语言。无法确认的内容必须进入待确认列表，而不是静默猜测。

### 导出流程

1. 点击历史标题行右侧的圆形导出按钮。
2. 通过系统保存文件选择器选择位置和文件名，默认建议 `hercula-export-YYYY-MM-DD.json`。
3. 写出版本化 JSON；成功后提示保存位置，失败时保留原数据并显示可重试错误。

## 3. 视觉方向

### 色彩

| 用途 | 建议色 | 说明 |
| --- | --- | --- |
| 页面背景 | `#F7F1F2` | 低饱和暖白粉 |
| 主卡片 | `#F1DDE1` | 大面积柔和粉色 |
| 经期标记 | `#C98291` | 与背景有足够对比 |
| 当前日期强调 | `#A95E70` | 用于焦点和关键文本 |
| 对比点缀 | `#B8D1D5` | 浅蓝灰，只用于今天/辅助状态 |
| 正文 | `#594B50` | 避免纯黑的莫兰迪深色 |

颜色只是初始 token；开发时必须在真实设备上检查对比度、深色模式和系统字体放大效果。

### 形状、层次与动效

- 采用大圆角卡片，建议圆角 token 为 24vp，按钮不低于 16vp。
- 日历外层用多层半透明背景和渐变边缘制造“柔和包裹感”，不使用高成本实时模糊作为核心效果。
- 页面切换使用自然的纵向滑动和短时缓动；月历使用横向拖动和连续缓动切换月份；年月浮窗向下浮现。更多日期反馈和图表进入动效记录在 [UI 动效探索](./ui-motion-exploration.md)，待多设备基线确定后实现。
- 平板和宽折叠屏展开态使用居中的最大内容宽度、固定触控目标和紧凑日历行高；不以拉伸字号或无限增高卡片适配屏幕。
- 触控目标至少满足系统可用性要求；颜色不是唯一状态表达，必须配合日期数字、点、文本或图例。

## 4. 空状态与错误状态

- 无记录：显示“先记录今天，月迹会慢慢形成”，图表区域不画 0 高度柱。
- 只有 1 次经期：显示历史时长，但不显示下一次预测，并说明“至少需要更多完整记录”。
- JSON 导入失败：不删除或覆盖已有记录，显示失败原因。文本/OCR 导入未来需要显示成功日期数、重复数、失败片段数，并允许只导入可确认的部分。
- 导出失败：不删除或回滚已有记录，只显示失败原因和重试入口。
- 预测不确定：显示日期区间和“仅供记录参考”，不使用“准确”“安全期”等词。
