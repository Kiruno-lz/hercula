## 统一设计约束

- 以现有日历参考作为色彩、字号层级、圆角、透明度和留白基准。
- 每个有界面的组件先生成关闭/展开/空状态/错误状态等必要渲染图，再讨论代码结构。
- 渲染图只确认视觉和交互状态，不直接视为 ArkUI 最终实现；最终实现必须遵循组件边界和窗口响应式布局文档。
- 组件不创建第二份业务数据源；导入、导出、日期记录和确认动作最终回到统一页面状态。
- 设计稿优先覆盖 Pura X 展开竖向、Pura X 展开横向双排和 Pura X 折叠态；无法在紧凑窗口容纳的非核心内容必须可隐藏或降级。
- 当前简单文本导入只支持明确年月日分隔符，解析后进入 JSON schema 候选确认；不引入自然语言模型或 OCR。

## 已完成第 1 项：可展开操作按钮与菜单

已生成两态设计稿：

- 关闭态：标题行右侧的轻量圆形操作按钮。
- 展开态：按钮从原位置向下/向内连续变形为半透明圆角菜单面板。
- 菜单项：`导入日期`、`导出日期`、`关于软件`。
- 交互：点击任意菜单项进入对应流程；点击面板外任意位置关闭；面板内部不设置 close button。
- 动效：优先使用 transform、opacity 和圆角/尺寸连续变化表达 morph；系统减少动效时降级为即时展开/关闭。

设计参考：[Transitions.dev Dropdown menu morph](https://transitions.dev/detail.html?t=dropdown-menu-morph)。该参考提供 CSS/React 的网页实现，月迹只借鉴“按钮变形为菜单表面”的运动关系，不引入 Web 或 React 依赖。

## 当前第 2 项：文本日期导入输入框

当前渲染稿包含两个状态：

- 空输入态：显示示例格式和获得焦点后的输入区域。
- 已输入态：展示多种明确日期分隔符的示例；JSON 加载后将有效日期回填为标准 `YYYY-MM-DD` 行文本。
- 组件形态：使用覆盖在当前页面上的浮动窗口，不占据整面页面。
- 尺寸规则：初始窗口保持约 1:1；窗口高度随内容自然增长；当内容高度达到外部容器的 80% 时，窗口固定在该上限以内，仅输入区域启用内部滚动，底部操作按钮保持可见。
- 输入范围：`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY.MM.DD`、`YYYY年MM月DD日`。
- 操作：`从 JSON 文件加载` 通过系统文件选择器读取并回填，`取消` 返回上一个界面，`继续` 进入下一项“JSON/文本导入确认界面”。

## 当前第 3 项：JSON/文本导入确认界面

当前渲染稿包含两个状态：

- 全部有效：展示识别总数、新增数、重复数，以及每条日期的状态。
- 部分失败：展示可导入数量和失败数量；无效日期使用低饱和警示色，失败内容不会写入记录。
- 日期过多滚动态：窗口高度达到外部容器约 80% 后保持不变，日期列表区域独立滚动，标题、摘要和底部操作按钮固定可见。
- 三态对照稿：全部有效、部分失败和日期过多滚动态的窗口外框高度、上下基线和底部按钮位置保持一致；仅调整内部列表可视区域。
- 操作：`取消` 不改变本地数据；确认按钮只导入有效且去重后的日期。
- 窗口：继续使用浮动液态玻璃窗口，内容多时允许动态增高并受外部容器高度限制。

## 每项完成标准

1. 明确组件的使用场景和状态集合。
2. 生成渲染图并完成视觉 review。
3. 补充尺寸、间距、颜色、文字和手势规则。
4. 在当前 ArkUI 工程中实现并通过编译。
5. 在相关模拟器画布检查位置、裁剪、字体和交互回归。
