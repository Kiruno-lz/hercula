# 月迹可执行实施方案

## 1. 阶段与出口

### Phase 0：开发环境基线

已建立 DevEco Studio 工程，使用 DevEco 内置 HarmonyOS SDK，完成命令行构建，并在 Pura X 宽折叠模拟器安装启动。DevEco 模拟器是当前多设备布局验证的主要环境；真机验证降为发布前补充项。

出口：命令行构建和模拟器安装启动已通过；签名、文件选择器异常和重启恢复仍需验证。编译器当前仅剩 ArkTS 异常处理提示、弃用 API 提示和未配置签名提示。

### Phase 1：领域核心

实现 `YYYY-MM-DD` 日期工具、每日记录模型、以每个记录日作为经期起点的时长统计和基础预测算法。当前规则是：本条记录到下一条记录的日期差作为时长；最后一条记录统计到今天且最短为 1 天。纯业务测试仍需补齐。

出口：不依赖 UI 即可通过测试覆盖跨月、跨年、闰年、重复日期、未来日期、进行中和预测不足场景。

### Phase 2：本地存储与导入导出

实现版本化 JSON schema、PreferencesStore、JSON 导入、简单文本日期导入、导入预览/确认、系统文件读取与保存。当前已完成版本化 JSON 导入导出、系统 Picker、未来日期过滤和导入确认；严格字段错误报告和文本日期解析仍待实现。文本只处理明确的年月日分隔符并归一化为 JSON 候选，OCR 导入和 AI 解析暂时搁置。规格见 [JSON Schema](../json_SPEC.md)。

出口：导出文件可再次导入且数据等价；损坏文件不会覆盖旧数据；导入失败能定位到片段。

### Phase 3：日历与记录闭环

实现自绘紧凑月历、任意可见的过去日期标记/取消、未来日期无响应、横向月份切换、年/月快速跳转、首次欢迎弹窗和 Preferences 恢复。界面 1 已按 Pura X 宽折叠展开态完成视觉确认；其他形态尚未完成正式适配。多设备重排必须在功能和基础 UI 组件稳定后进行。

出口：用户可以不经过其他页面完成“任意日期标记—再次点击撤销—关闭应用—重新打开—仍然存在”。

### Phase 4：历史图表与分页体验

实现纵向 Swiper 两页、无边框横向水平柱状图、日期倒序、动态长度、短柱体 3vp 视觉偏移、跨年空隙年份标识、空状态和进行中状态。导出按钮已移动到“月经历史”标题行右侧；有历史时不显示导入按钮。

出口：任意 0、1、3、12、120 条记录都不溢出；横向标签可读；单次手势能完成整页切换；跨年标识不增加列表行高。长列表滚动和多设备排版仍需验证。

### Phase 5：基础组件与响应式布局

先完成领域功能、JSON schema 校验和基础 UI 组件，再拆分 `Index.ets`。随后以窗口断点组织单列与双排布局，重点验证 Pura X 展开横向双排；最后再做额外动效和设备兼容检查。

出口：基础组件可独立预览；单列与双排布局共用同一份状态和事件契约；五个模拟器规格的截图、交互和窗口切换行为通过检查。

### Phase 6：质量与上架准备

完成更多 UI 动效、隐私政策、应用图标和截图、签名、AppGallery Connect 测试发布、兼容性与隐私检查。Buy Me a Coffee 卡片需要先确定平台链接和展示位置。

出口：测试轨道安装包可重复构建；发布资料、权限清单、数据处理说明和已知限制齐全。

## 2. 推荐开发顺序

```text
工具链验证
  -> 日期/分组/预测纯逻辑
  -> 本地存储
  -> JSON 导入导出
  -> 日历记录闭环
  -> 历史图表
  -> JSON schema 严格校验
  -> 简单文本日期解析与确认
  -> 基础 UI 组件拆分
  -> 多设备响应式布局与 Pura X 横向双排
  -> 模拟器兼容检查
  -> 动效增强
  -> 隐私、签名、上架
```

每个阶段结束都保留一个可运行版本。禁止先铺开完整视觉系统、端侧 AI 或复杂数据库，再补核心记录流程；复杂文本语义和 OCR 保留为后续独立议题，简单文本日期解析按确定性规则推进。

## 2.1 多设备基线与组件拆分顺序

多设备适配必须先固定窗口形态和内容优先级，但不需要等所有最终视觉稿完成后才拆组件。先抽取稳定的基础 UI 组件和状态/事件契约，再由响应式页面壳决定单列或双排。第一轮验证以下窗口：

| 形态 | 画布 | 首轮布局重点 |
| --- | --- | --- |
| Pura X 展开竖向 | 1320×2120 | 界面 1 当前基准；品牌、年月控件、月历完整展示 |
| Pura X 折叠 | 980×980 | 只保留核心月历组件，不展示 logo 和非必要说明 |
| Pura X 展开横向 | 2120×1320 | 双排展示目标；左侧日历、右侧历史统计独立滚动，共用状态和导入导出规则 |
| 折叠屏展开 | 2210×2416 | 保持主内容居中，宽度足够时允许双排，避免按整屏宽度拉伸日期触控目标 |
| 折叠屏折叠 | 1080×2444 | 按直板窄屏规则排版，保持标题、年月控件和月历纵向层级 |
| 直板屏 | 1320×2856 | 保持当前视觉比例，检查上下留白和历史页长列表 |

组件拆分顺序：先抽设计 token、窗口度量和日期/历史视图模型，再抽 `CalendarPage`、`MonthJumpPanel`、`HistoryPage`、`HistoryChart`，最后抽导入导出动作和页面状态。组件先在当前单列 UI 中替换并保持视觉不变，再由 `ResponsivePageShell` 组合单列或双排。每个组件必须通过 `@Prop`/`@Link` 或明确的回调接收状态，不直接持有 Preferences。

拆分出口：基础组件独立预览并通过默认属性初始化；单列和双排使用同一数据源、同一日期交互和同一导入导出契约；Pura X 折叠态不加载 logo；年月浮窗、月份拖动和纵向分页不互相抢手势。

- [x] 首次打开显示一次欢迎弹窗，支持开始记录或进入导入流程。
- [x] 自绘月历支持横向换月、年/月快速跳转，不显示星期标题和月份箭头。
- [x] 记录日到下一记录日的时长规则已接入；最后一条统计到今天，最短为 1 天。
- [x] 当前最后一条记录在图表中显示为“进行中”。
- [x] 历史不足时不显示预测日期。
- [x] JSON 导入导出闭环，schema 有版本号。
- [ ] 文本导入可预览、可取消、可处理部分失败。
- [x] 导入和导出都经过系统文件选择/保存能力。

- [ ] 系统字体放大、深色模式、无障碍朗读、窄屏、平板、折叠态和宽折叠展开布局可用。

## 4. 关键风险与处理

| 风险 | 处理 |
| --- | --- |
| 把“任意文本”误解成可 100% 自动识别 | 定义支持格式；保留候选与确认；无法确认不静默写入 |
| 误把预测当成医疗结果 | 使用透明统计和“估算/参考”措辞；样本不足不预测 |
| 使用错误或过期 API | 工程初始化时锁定 SDK；每个 Kit 以当前 API Reference 编译验证 |
| 通过路径直接访问公共文件 | 只使用系统 Picker 返回的 URI；优先用模拟器验证授权生命周期，发布前再补充真机检查 |
| 图表只好看但不可读 | 同步提供文字摘要、柱条末端数值和无障碍描述 |
| 视觉需求挤压核心闭环 | 先完成 Phase 1–3，再做渐变装饰和精细动效 |

## 5. 后续决策点

以下内容不应在没有验证前写入首版代码：

- 端侧 AI 的具体 Kit、模型大小、离线覆盖率和数据处理边界。
- 系统级备份是否开启，以及备份数据是否仍符合“本地隐私”的产品承诺。
- 是否允许直接编辑历史日期；这会影响日历交互、数据模型和误操作保护。
- 平板/折叠屏首版采用最大宽度约束和固定触控目标；Pura X 展开横向明确纳入双排布局验证，其他宽屏仅在容器宽度足够时复用该布局。
- 多设备断点与布局基线：先抽稳定的基础 UI 组件和接口，再确定 Pura X 折叠态、Pura X 展开态、Mate X7 展开/折叠态和直板屏的容器组合；不能以当前单一屏幕的绝对坐标直接抽成通用组件。
- 真机验证：不作为当前布局开发的前置条件；仅在模拟器无法复现窗口、系统文件授权或性能问题时补充。
- 本地 AI/OCR：暂缓；简单文本导入必须先转为 `json_SPEC.md` 定义的候选结构，再经过用户确认。
- Buy Me a Coffee：需要决定收款平台、公开链接、是否放 README 以及是否进入应用内设置页。
