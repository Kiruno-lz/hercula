# 响应式布局与组件边界探索

调研日期：2026-08-14。本文件解决两个架构问题：Pura X 展开横向时如何呈现日历与历史双排，以及 `Index.ets` 应在什么时机拆分。

## 探索原因

当前 `Index.ets` 同时承担页面状态、日期事件、月历绘制、历史统计、导入导出和页面手势。若直接在这个文件中追加设备判断，单列、双排和紧凑布局会逐渐形成多套互相耦合的分支；若在功能和基础组件尚未稳定前一次性拆分，又会把暂时的视觉结构固化成错误的组件接口。

项目还新增了明确的场景：Pura X 展开并横向放置时，需要让日历和历史统计同时展示。这个场景不是简单缩放当前竖向页面，必须调整外层布局和手势策略，同时保持日期记录、预测和 JSON 导入导出只有一个数据源。

## 探索目标

1. 确定 ArkUI 中按窗口状态切换单列、双排和紧凑布局的实现边界。
2. 确定基础 UI 组件、响应式页面壳与领域状态之间的职责。
3. 在不提前制造设备专用页面的前提下，给出可以逐步落地的 `Index.ets` 拆分顺序。
4. 明确 DevEco 模拟器与真机在当前阶段的验证优先级。

## 探索结果

### 1. 按窗口能力选择布局，不按设备型号选择页面

ArkUI 官方多设备布局资料推荐使用响应式布局和断点来调整列数、行数与内容组合；`GridRow`/`GridCol` 适合表达结构性断点。窗口宽高应从当前窗口属性获取，而不是把设备型号或单一屏幕像素直接写进业务组件。

月迹采用三种布局模式：

| 模式 | 进入条件 | 页面表现 | 手势策略 |
| --- | --- | --- | --- |
| `compact` | 小方形或可用宽度不足 | 只保留核心月历，Pura X 折叠态不展示 logo | 保留日期点击和月内换月 |
| `single` | 竖向窗口、直板屏或宽度不足以并列 | 月历与历史保持两个纵向整页 | 外层纵向分页，月历内部横向换月 |
| `dual` | Pura X 展开横向，或其他窗口宽度足够 | 左侧月历，右侧历史统计 | 取消两个功能区之间的纵向分页，只保留月历内部横向换月 |

`dual` 是页面组合变化，不是领域模型变化。日历和历史组件接收同一份 `PageState`，导入、导出和日期事件仍由页面状态层统一处理。

### 2. Pura X 展开横向的双排方案

首个双排验收目标为 Pura X 展开横向，即竖向基准画布 `1320×2120` 旋转后形成 `2120×1320` 的窗口样本：

```text
┌──────────────────────┬──────────────────────┐
│                      │                      │
│      CalendarPage    │      HistoryPage     │
│      月历与跳转       │      预测与历史统计    │
│                      │                      │
└──────────────────────┴──────────────────────┘
```

实施约束：

- 两列使用稳定的最大内容宽度和内部留白，不把日期格拉伸到整屏宽度。
- 左列继续支持月份横向拖动；右列的历史列表独立滚动或在自身可用区域内裁剪，不能抢走左列的月份手势。
- 双排时不显示“向上滑动查看历史”的引导，也不依赖纵向 `Swiper` 才能到达历史页。
- 窗口回到窄宽度时，布局壳恢复单列，两个组件继续使用同一状态，不重新加载或迁移数据。
- 其他展开屏只在可用宽度和折叠状态满足条件时复用双排；不能因为“展开”二字强制双排。

### 3. 先拆基础组件，再做最终重排

候选顺序比较如下：

| 方案 | 判断 | 原因 |
| --- | --- | --- |
| 先把所有 UI 重排完成，再从 `Index.ets` 拆分 | 不采用 | 单文件会同时承载多种布局和临时状态，最终拆分时难以判断真正稳定的边界 |
| 现在一次性拆出完整设备组件树，再开始功能完善 | 不采用 | 当前交互和数据契约仍在收敛，容易把单列视觉细节错误地封装成设备专用组件 |
| 先完成基础功能与基础 UI 组件，再抽响应式页面壳，最后重排 | 采用 | 组件边界来自稳定功能，布局差异集中在页面壳，能够保持单列回归并渐进加入双排 |

推荐顺序：

1. 完成当前核心功能和 JSON schema 严格校验。
2. 从 `Index.ets` 抽出 `CalendarPage`、`MonthJumpPanel`、`HistoryPage`、`HistoryChart`、导入导出动作和设计 token；先在单列页面中做到视觉与交互不变。
3. 抽出 `ResponsivePageShell`，只负责窗口度量、布局模式和手势策略。
4. 先实现 `single` 与 `compact` 回归，再实现 Pura X 展开横向的 `dual`。
5. 在五个模拟器画布上做截图、交互和窗口切换检查，最后再补充动效。

组件不直接访问 Preferences。页面状态层负责读取和写入，组件只通过 `@Prop`、`@Link` 或明确回调接收数据和发出事件；组件预览必须为本地初始化属性提供默认值，以避免 DevEco 预览器的 `mandatory-default-value-for-local-initialization` 问题。

### 4. ArkUI 能力映射

| 需求 | 建议能力 | 在月迹中的边界 |
| --- | --- | --- |
| 结构性断点 | `GridRow` / `GridCol` 或等价的容器布局 | 只由响应式页面壳使用，不让领域组件判断设备 |
| 窗口尺寸 | 窗口属性 `windowRect` | 在页面可见阶段读取，变化时刷新布局度量 |
| 折叠/旋转避让 | 窗口避让区变化监听；必要时评估折叠布局容器 | 先满足 Pura X 横向双排，不引入超出需求的设备专用容器 |
| 组件状态 | ArkUI V1 当前工程使用的状态装饰器和回调 | 保持现有 SDK/API 版本可编译，不在本阶段迁移状态管理范式 |

## 复现说明

当前不需要新增实验代码。按下面的模拟器样本检查即可：

1. 以 `1320×2120` 验证当前 Pura X 展开竖向单列基准。
2. 以 `2120×1320` 验证 Pura X 展开横向双排：左侧月历、右侧历史；日期点击和导出动作仍有效。
3. 以 `980×980` 验证紧凑月历，不加载 logo。
4. 以 `2210×2416`、`1080×2444`、`1320×2856` 验证宽度不足时回退单列、宽度足够时不发生异常拉伸。
5. 在窗口横竖切换或折叠变化后，检查状态不丢失、月份不重置、导入导出不重复触发。

## 注意事项与补充

- DevEco 模拟器是当前布局和交互验证的主要环境；真机不是组件拆分或多设备适配的前置条件，只有模拟器无法覆盖系统授权、性能或窗口异常时才补充。
- 不使用设备型号字符串作为业务分支。设备型号可以用于测试记录，但不能作为 `CalendarPage` 或 `HistoryPage` 的输入。
- 不把双排布局实现成两套 Preferences、两套预测或两套导入导出流程。
- 简单文本日期导入按确定性分隔符规则推进，并统一转换为 `docs/json_SPEC.md` 候选；复杂文本语义和 OCR 导入暂时搁置。
- 动效排在基础组件和布局回归之后；双排模式先保证信息层级、滚动边界和手势隔离，再增加动画。
