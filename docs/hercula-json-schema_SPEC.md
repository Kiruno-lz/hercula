# hercula JSON 数据规格（SPEC）

状态：规范草案 v1，作为首版 JSON 导入/导出的唯一数据契约。

## 1. 目标与边界

本规格只定义用户主动导入或导出的 JSON 文件，不定义 Preferences 内部键值的存储细节。文件用于备份、迁移和人工检查；应用内部仍以日期集合为事实来源，周期时长和预测结果不写入文件。

v1 只保存用户记录的经期日期。未来日期不是有效的经期事实，导入时不得进入应用状态。

## 2. 文件结构

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-08-14T08:00:00.000Z",
  "days": [
    {
      "date": "2026-05-09",
      "source": "manual"
    },
    {
      "date": "2026-06-16",
      "source": "import"
    }
  ]
}
```

## 3. 字段约束

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `schemaVersion` | integer | 是 | v1 必须为 `1` |
| `exportedAt` | string | 是 | ISO 8601 时间；仅表示导出时间，不参与经期计算 |
| `days` | array | 是 | 可为空；每个日期最多一条 |
| `days[].date` | string | 是 | 本地日历日期，格式 `YYYY-MM-DD`，必须是合法日期 |
| `days[].source` | string | 是 | 只能是 `manual` 或 `import` |

文件应使用 UTF-8 编码。日期按升序写出，重复日期在导出前去重。未知字段暂时忽略，但不得改变已知字段的含义。

## 4. 导入策略

1. 先读取并解析 JSON，不修改现有记录。
2. 验证版本、数组结构、日期格式、合法日期和来源枚举。
3. 过滤未来日期，并在预览中明确显示被过滤数量。
4. 显示有效日期数、重复数和新增数。
5. 只有用户确认后，才与本地日期集合合并并持久化。

当前实现已经完成 v1 文件选择、版本检查、去重、预览确认和合并；严格字段验证、未来日期过滤数量展示和结构化错误信息仍是 TODO。

## 5. 版本策略

- 不修改 v1 字段的既有语义；新增字段只在新版本规格中定义。
- 读取未知 `schemaVersion` 时拒绝导入，不猜测兼容关系。
- 新版本读取旧版本时必须显式迁移，并保留原始文件不变。
- 导出始终生成当前应用支持的最高版本。

## 6. 验收样例

- 空数组可导入，结果为空状态。
- 重复日期只保留一条。
- `2024-02-29` 在闰年有效，`2025-02-29` 无效。
- 未来日期不写入本地记录。
- `schemaVersion: 2`、缺失 `days`、非法来源和非法日期均不能覆盖已有数据。
- 导出后再次导入，日期集合与导出前等价。
