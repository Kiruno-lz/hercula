# 文本与 JSON 导入测试案例

以下案例用于 DevEco 模拟器手工验证。为了固定“未来日期”的结果，验证时将模拟器日期视为 `2026-08-14`。

## 文本输入案例

### 全部有效

```text
2026-05-09
2026/06/16
2026.07.18
2026年08月10日
```

预期：识别 4 条，可导入 4 条，无重复，无失败。

### 重复日期

```text
2026-08-10
2026/08/10
2026年8月10日
```

预期：输入框保持标准日期候选，确认窗口报告重复日期；只写入 1 条。

### 无效日期和未来日期

```text
2026-02-29
2026-08-14
2026-09-01
```

预期：`2026-02-29` 标记无效，`2026-09-01` 标记未来日期，`2026-08-14` 可导入。

### 不支持的表达式

```text
26-08-14
20260814
2026年8月14
```

预期：不猜测年份或缺失的“日”后缀，全部进入失败内容。

## JSON 文件案例

- [`valid-history.json`](./valid-history.json)：全部有效日期。
- [`duplicates-and-future.json`](./duplicates-and-future.json)：重复日期、已有日期和未来日期组合。
- [`mixed-validity.json`](./mixed-validity.json)：合法日期与非法日期混合，进入部分失败确认态。
- [`invalid-schema.json`](./invalid-schema.json)：不支持的 schema 版本，选择后应拒绝回填并提示 schema 错误。

所有案例都必须先回填/解析，再由确认窗口决定是否合并；文件选择、解析或确认取消都不得改变已有记录。
