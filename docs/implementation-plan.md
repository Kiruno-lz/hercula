# 月迹可执行实施方案

## 1. 阶段与出口

### Phase 0：开发环境基线

建立 DevEco Studio 工程，选择当前稳定 HarmonyOS SDK，确认可在模拟器或真实设备运行空白 ArkTS 页面。提交工程配置、包名、签名策略和实际版本记录。

出口：空白应用可安装、启动、退出；无网络权限；构建日志无未解决告警。

### Phase 1：领域核心

实现 `YYYY-MM-DD` 日期工具、每日记录模型、连续经期分组、时长统计和预测算法。先写纯业务测试，再接 Preferences。

出口：不依赖 UI 即可通过测试覆盖跨月、闰年、重复日期、进行中和预测不足场景。

### Phase 2：本地存储与导入导出

实现版本化 JSON schema、PreferencesStore、JSON 导入、规则文本解析、导入预览/确认、系统文件读取与保存。所有写入都走单一 repository。

出口：导出文件可再次导入且数据等价；损坏文件不会覆盖旧数据；导入失败能定位到片段。

### Phase 3：日历与记录闭环

实现月历网格、当前日期状态、点击/撤销确认、应用重启恢复。先用静态 token，再补渐变、圆角和动效。

出口：用户可以不经过其他页面完成“今天标记—关闭应用—重新打开—仍然存在”。

### Phase 4：历史图表与分页体验

实现纵向 Swiper 两页、无边框横向水平柱状图、文本摘要、空状态和进行中状态。图表先保证日期标签、柱条末端时长和可读性，再加入装饰渐变。

出口：任意 0、1、3、12、120 条记录都不溢出；横向标签可读；单次手势能完成整页切换。

### Phase 5：质量与上架准备

完成真机适配、隐私政策、应用图标和截图、签名、AppGallery Connect 测试发布、兼容性与隐私检查。

出口：测试轨道安装包可重复构建；发布资料、权限清单、数据处理说明和已知限制齐全。

## 2. 推荐开发顺序

```text
工具链验证
  -> 日期/分组/预测纯逻辑
  -> 本地存储
  -> JSON 与文本导入导出
  -> 日历记录闭环
  -> 历史图表
  -> 视觉与动效
  -> 真机、隐私、上架
```

每个阶段结束都保留一个可运行版本，禁止先铺开完整视觉系统、AI 解析或复杂数据库，再补核心记录流程。

## 3. 首版验收清单

- [ ] 新用户不联网也能启动并完成今天的记录。
- [ ] 重复点击不会生成重复日期；撤销有确认。
- [ ] 跨月、跨年和闰年统计正确。
- [ ] 当前记录在图表中显示为“进行中/截至今天”。
- [ ] 历史不足时不显示伪精确预测。
- [ ] JSON 导入导出闭环，schema 有版本号。
- [ ] 文本导入可预览、可取消、可处理部分失败。
- [ ] 导入和导出都经过系统文件选择/保存能力。
- [ ] 应用不申请网络权限，不集成统计或云服务 SDK。
- [ ] 系统字体放大、深色模式、无障碍朗读和窄屏布局可用。
- [ ] 真机上验证应用重启、权限撤销、文件保存失败和异常 JSON。

## 4. 关键风险与处理

| 风险 | 处理 |
| --- | --- |
| 把“任意文本”误解成可 100% 自动识别 | 定义支持格式；保留候选与确认；无法确认不静默写入 |
| 误把预测当成医疗结果 | 使用透明统计、区间和免责声明；样本不足不预测 |
| 使用错误或过期 API | 工程初始化时锁定 SDK；每个 Kit 以当前 API Reference 编译验证 |
| 通过路径直接访问公共文件 | 只使用系统 Picker 返回的 URI；真机验证授权生命周期 |
| 图表只好看但不可读 | 同步提供文字摘要、柱条末端数值和无障碍描述 |
| 视觉需求挤压核心闭环 | 先完成 Phase 1–3，再做渐变装饰和精细动效 |

## 5. 后续决策点

以下内容不应在没有验证前写入首版代码：

- 端侧 AI 的具体 Kit、模型大小、离线覆盖率和数据处理边界。
- 系统级备份是否开启，以及备份数据是否仍符合“本地隐私”的产品承诺。
- 是否允许直接编辑历史日期；这会影响日历交互、数据模型和误操作保护。
- 是否需要平板/折叠屏专属布局；首版先完成手机窄屏和普通手机宽屏。
